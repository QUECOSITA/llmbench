# Security Policy

## Supported Versions

We actively monitor and patch vulnerabilities only for the versions listed below. Please upgrade to a supported version to ensure your environment remains secure.

| Version | Supported          |
| ------- | ------------------ |
| 0.1.0>   | :white_check_mark: |


## Reporting a Vulnerability

**Please do not open public GitHub issues for security vulnerabilities.** 

We take the security of our project seriously. If you discover a vulnerability, please report it responsibly using one of the following methods:

### Method 1: GitHub Private Vulnerability Reporting (Preferred)
If enabled on this repository, please navigate to the **Security** tab of this repository, select **Vulnerabilities**, and click **Report a vulnerability** to submit a private report.

### What to Include in Your Report
To help us triage and patch the issue quickly, please include:
* A detailed description of the vulnerability and its potential impact.
* Clear, step-by-step instructions or a Proof of Concept (PoC) script to reproduce the issue.
* Any specific configurations, environment details, or dependencies required to trigger it.

## Our Response Process

* **Acknowledgement:** We will acknowledge receipt of your report within **48 hours**.
* **Triage & Fix:** We will evaluate the risk and work on a fix. We aim to resolve valid vulnerabilities within **30 days**.
* **Disclosure:** We follow coordinated vulnerability disclosure. We will coordinate with you to publish a Security Advisory alongside the patch release.

Thank you for helping keep this project secure!
